# Code of Conduct

## Our standard

Contributors and maintainers are expected to create a professional, technically rigorous, and welcoming project environment.

Examples of constructive behavior include:

- discussing evidence, trade-offs, and version boundaries rather than attacking people;
- giving actionable review feedback;
- acknowledging uncertainty and correcting mistakes transparently;
- protecting credentials, private topology, customer data, and incident details;
- respecting different experience levels and operational environments;
- prioritizing database safety over speed or ego.

Unacceptable behavior includes harassment, personal attacks, discriminatory language, deliberate misinformation, credential disclosure, publishing private production details, or pressuring someone to execute unsafe database changes.

## Technical disagreements

Citus behavior can vary by PostgreSQL version, Citus version, edition, provider, topology, and query shape. Resolve disagreements through:

1. installed database metadata and reproducible tests;
2. official version-specific documentation and source;
3. representative staging evidence;
4. clearly documented assumptions and remaining uncertainty.

Do not present a benchmark heuristic or one provider's behavior as a universal rule.

## Enforcement

Repository maintainers may edit or remove comments, issues, pull requests, or contributions that violate this standard. Serious or repeated violations can result in temporary or permanent exclusion from project spaces.

Report conduct issues privately to the repository maintainers. Do not include credentials, customer data, or sensitive incident details in a public report.
